# Step 2: Your CV

## What this step does

It stores your CV as Markdown (plain text with simple formatting) and
confirms the employment history, education and skills that were read from it.
Without a CV nothing can be evaluated against your experience and no résumé
can be written. The product never invents experience: only what you confirm is
used.

## Before you start

Choose a PDF, DOCX, Markdown or plain-text CV, or paste its text. In Setup or
Profile, **Import from file** puts extracted text into the editor; review and
edit it, then **Save CV**. A PDF or DOCX comes in with its name, section
labels, dated entries and bullets marked as Markdown headings and list items;
the words are the document's own. Importing over text you have not saved asks first.
A save quotes the version of `cv.md` the editor loaded: if the CV was saved
meanwhile in another window, nothing is written and you choose **Keep my text**
(the next save replaces the newer CV) or **Load the new version**. When nothing
is typed over the loaded text, a CV saved elsewhere replaces it as the window
comes back into view. Interactive `applysmith setup` shows the extracted text
and asks before saving it. PDF extraction uses local Poppler (`pdftotext`);
DOCX extraction needs no additional install. Neither calls a model or uploads
the document to an external service. Extracted text shorter than 200 characters
is rejected; paste the CV text instead (or apply OCR to scanned pages).

## Steps

To import a file and review its text in the terminal:

```
applysmith cv import my-cv.pdf --workspace <dir>
```

It prints the extracted text and profile draft, defaults to **no**, and saves
only `cv.md` after confirmation. It uses the normal workspace lock and CV
backup/revision checks; it does not open the database or approve profile facts.
For scripted confirmation, use `--answers <file|->` with a `yes` line after
reviewing the selected file. A running server holds the workspace lock; use
the dashboard or stop that server before a CLI import.

Put the CV into a JSON file, for example `cv.json`:

```json
{
  "markdown": "# <your name>\n\n## Experience\n..."
}
```

```
applysmith setup apply cv --file cv.json --dry-run
applysmith setup apply cv --file cv.json
```

Applysmith reads a draft of your employment, education and skills out of the
text. Review the draft in the dashboard (Profile page, or the Setup wizard):
confirm or discard each entry. In the Setup wizard each kept entry's employer,
title, school, degree, skill name and dates can be corrected before you
confirm, and a refusal is shown beside the entry it names. A date given only as
a year needs its month (YYYY-MM). An entry removed there is recorded as
discarded, so the Profile page does not offer it again. Or confirm entries from the command line by sending them yourself:

```
applysmith setup schema cv
```

The fields are `employment`, `education` and `skills` (the confirmed lists,
which replace the stored ones), `revision` (the `cv.md` revision your
`markdown` was edited from; a newer file is not replaced) and `review_complete` (say the draft was
reviewed even if you confirmed nothing). Omit `markdown` to keep the stored CV.

If the CV still contains the fictional persona's text and you really mean it:

```
applysmith setup ack cv
```

## Optional: bring in several documents

One CV, or typing your history by hand, is all this step needs. If you also
have older CV versions, an exported profile, an education record, project
descriptions, references, a course outline or a repository README, you can
select up to 20 of those files and compare them with your profile before
anything is stored. Each file is a `.md` or `.txt` file you name yourself; no
folder is searched and no link is followed.

```
applysmith setup intake preview cv-2024.md education-record:registrar.md course:outline.txt
```

The preview prints the profile revision it was built from and every item with
its source (document label, content hash, line and heading):

- **new**: an entry the profile lacks. Applying it needs your selection.
- **conflict**: a date, title, institution or employer that a document gives
  differently from your profile or from another document. Neither side wins on
  its own, file times play no part, and your approved value stays until you pick
  a side.
- **match**: already in your profile; nothing to apply.
- **signal**: a skill that a course outline, repository file, project
  description or reference mentions. That is a question, not a fact: it is not
  in your profile, your answer bank or your résumé drafts unless you confirm it.

To apply, write the items you chose as a JSON list and name the revision:

```
applysmith setup intake apply cv-2024.md education-record:registrar.md course:outline.txt --revision <revision> --select selections.json
```

```json
[
  {"id": "<new item>"},
  {"id": "<conflict item>", "choices": {"end": "2015-05"}},
  {"id": "<date given as a year>", "months": {"start": "2015-02"}},
  {"id": "<signal>", "confirm": true}
]
```

A conflict needs a `choices` value for each field (`keep` keeps your profile's
own value). A date a document gives only as a year needs its month in `months`.
A signal needs `confirm`. If `profile.yml` changed after the preview, the
request is refused and nothing is written; preview again. Importing the same
documents twice adds nothing: what is already in the profile shows as a match,
and a file with the same content as an earlier one in the batch is read once.
`cv.md` is never rewritten. The dashboard offers the same preview under
"Add more documents (optional)" on this step and on the Profile page.
Files inside the workspace's `documents` and `reports` folders are refused,
because they are generated from your profile and are not evidence.

## Where this is stored

The text is `cv.md` in your workspace. The confirmed history and skills are in
`profile.yml` (keys `history` and `skills`). A CV file is limited to 256 KiB of
UTF-8 text after extraction; selected files are limited to 10 MiB. DOCX main
text and referenced headers/footers are read locally, with 10 MiB of expanded
XML at most. Plain section labels such as `Experience`, `Education` and
`Technical Skills` are recognized by the same dated-entry parser as Markdown
headings; ordinary prose containing those words is not a heading. Formatting
is not reproduced; review the extracted text before
saving. Only confirmed entries are written to your profile.

## How to check it worked

```
applysmith doctor --only cv
```

```text
[PASS] cv.content   cv is complete
```

## If something goes wrong

| What you see | What to do |
|---|---|
| `cv.md still holds the seed text` | Send your own text with `setup apply cv`. |
| The text is rejected as too large or not UTF-8 | Save the file as UTF-8 and keep it under 256 KiB. |
| An entry you confirmed is wrong | Edit it on the Profile page; the stored list is whole-list, so the page saves the entire list. |
| `placeholder` findings | Text such as `[Your Name]`, `TODO` or `<company>` is still in the CV. Replace it. |
